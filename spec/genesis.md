# Genesis: how a conker gets its properties

Every conker is derived from two public inputs, so anyone can recompute it.

## Inputs

1. `S`: the issuer's signature over the fixed message `CONKERS-GENESIS-v1`,
   made with RFC 6979 deterministic ECDSA (secp256k1), so `S` is reproducible
   from the issuer key alone. Published once, with the issuer public key.
2. `serial`: a uint32, assigned at purchase, big-endian when hashed.

## Hash chain

```
h0 = sha256(S || serial_be32)
hn = sha256(h(n-1))        for n = 1..7
```

`h0` is the pair id (links nut and string) and the cosmetic seed.

## Properties

`u32(h)` is the first four bytes of `h` as a big-endian unsigned integer.
All stored values are integers; the unit column says what they mean.

| Property | Cell | Formula | Range | Unit |
|---|---|---|---|---|
| mass | nut | `500 + u32(h1) mod 1501` | 500–2000 | centigram (5.00–20.00 g) |
| volume | nut | `200 + u32(h2) mod 1001` | 200–1200 | centi-cm³ (2.00–12.00 cm³) |
| hardness | nut | `1 + u32(h3) mod 100` | 1–100 | — |
| elasticity | nut | `20 + u32(h4) mod 61` | 20–80 | percent (0.20–0.80) |
| string length | string | `20 + u32(h5) mod 21` | 20–40 | cm |
| string strength | string | `10 + u32(h6) mod 51` | 10–60 | N |
| string elasticity | string | `u32(h7) mod 31` | 0–30 | percent (0.00–0.30) |

Density is derived: `mass / volume`. It is not stored.

## Inscription

Each cell's payload carries `{proto:"conkers", v:1, part:"nut"|"string", serial, genesisSig, issuer, props, pair}`.
A verifier recomputes `props` from `genesisSig`, `issuer` and `serial` and rejects a mismatch.

## Vectors

`spec/vectors.json` is generated by `mirror/scripts/make-vectors.ts` once the issuer key exists.
Until then the mirror's tests check determinism and ranges only.
